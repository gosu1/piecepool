# Graph View — 관계 논리와 계층 표현

> 그래프 뷰가 12개 RelationType 을 어떤 논리적 근거로 분류·시각화하는지의 설계 문서.
> 관계 타입 자체의 정의(SSOT)는 [../10-contracts/relation-types.md](../10-contracts/relation-types.md) — 본 문서는 **표시 계층만** 다루며 계약을 변경하지 않는다.
> 구현: `src/lib/relationMeta.ts`(분류·라벨·문장·계층 깊이) · `src/lib/CytoscapeGraph.tsx`(렌더링) · `src/lib/MiniGraph.tsx`(위키 문서 미니 로컬 그래프) · `src/app/panes/GraphSection.tsx`(칩·토글·패널).

## 1. 논리 분류 — 12타입 → 5그룹

관계의 논리적 성질(이행성·대칭성·반대칭성)로 나눈다. 사용자는 12타입이 아니라 시각 규칙 3개만 외운다.

| 그룹 | 멤버 | 논리 성질 | 시각 언어 |
| --- | --- | --- | --- |
| 구조·순서 `hier` | `part_of` `prerequisite` | 이행적·반대칭 → 부분순서(DAG). **유일한 계층축** | 실선 + 화살표. 세로 위치가 곧 의미 |
| 인과·활용 `flow` | `causes` `solves` `used_in` | 방향 있음, 개념 계층은 아님 | 실선 + 화살표 |
| 연관 `assoc` | `related_to` `contrasts` `confused_with` | **대칭** — 방향 무의미 | 점선, **화살표 없음** |
| 출처·문서 `prov` | `extracted_from` `explained_by` `tested_in` | 노드 타입 교차(→ Source/WikiPage) | 점선, 낮은 불투명도(배경) |
| 복습 `review` | `review_needed` | 사용자 전용 상태 마킹 | 점선, **유일한 색 = 빨강** |

- is-a(분류학적 상하위)는 12 enum 에 없음 — 계층축은 part_of(부분전체론)·prerequisite(학습 순서)로 유도한다.
- 대칭 관계에 화살표를 그리면 "A가 B로 간다"는 거짓 정보가 된다 → 화살표 제거가 논리적으로 정확한 표현.

## 2. 계층 규칙 (위 = 기초/전체)

계약 §2 의미상 두 계층 타입 모두 **target 이 위**다:

- `A part_of B` — "A는 B의 구성 요소" → B(전체)가 위
- `A prerequisite B` — "A를 이해하려면 B가 선수" → B(기초)가 위

`computeDepth`: hier 엣지만으로 longest-path layering. `depth(source) ≥ depth(target)+1`, depth 0 = 최상위. LLM 생성 데이터라 사이클이 가능하므로 DFS 방문중 노드로 가는 back-edge 는 그 간선만 절단(데이터는 그대로 그려짐 — 오류의 정직한 시각화).

레이아웃은 **유기적 계층**(하이브리드): 기존 d3-force 물리 시뮬에 `forceY(row × layerGap)` 를 더해 세로축만 계층으로 고정한다. 드래그하면 출렁이다 놓으면 제 층으로 복귀(계층 자가 회복). 병합(전체 과목) 뷰는 space 군집이 목적이라 계층 미적용. 계층 관계가 0개면 자동으로 기존 force 배치로 폴백.

행은 위에서부터 `depth 0..maxDepth` → **미순위**(계층 엣지가 없는 노드) → **고립**(엣지가 아예 없는 노드) 순이다. 계층 정보가 없는 노드에 depth 를 **지어내지 않는다** — 대칭 관계(`contrasts`·`confused_with`)로 이어진 두 개념은 대등하고(relation-types.md §7.1), `causes` 는 극성이 반대다. 대신 계층 밴드 아래 미순위 영역으로 약하게(0.08) 당겨, 세로 위치가 의미를 갖는 노드와 갖지 않는 노드를 화면에서 분리한다. 링크 힘(0.4)이 더 세므로 계층 노드에 매달린 미순위 노드는 여전히 이웃 곁에 정착한다 — 다만 최상위 개념 위로 떠오르지는 않는다.

배치 물리는 `src/lib/graphLayout.ts` 의 순수 함수다. `d3-force` 의 초기 배치는 결정적(phyllotaxis)이고 유일한 난수원인 `jiggle` 은 `simulation.randomSource()` 로 주입할 수 있어, 시뮬 전체가 재현 가능하다 — 배치는 `graphLayout.test.ts` 에서 실제로 단언한다.

## 3. 모노크롬 엣지 언어

색이 아니라 **모양**이 의미를 나른다 (색은 space 구분·복습 경고에만).

"그래프 읽는 법" 오버레이 문구. 앞 두 줄은 **계층 모드에서만** 노출한다 — 자유 배치(force)에서는 세로축이 radial 이라 "위=기초"가 성립하지 않으므로 그 말을 하지 않는다.

1. (계층 모드) 위에 있을수록 기초·전체 개념, 아래로 갈수록 세부
2. (계층 모드) 계층 관계가 없는 개념은 아래쪽에 따로 모임 — 그 높이는 의미 없음
3. 실선 = 뼈대(구조·인과), 점선 = 느슨한 연결 — 빨간 선은 복습 표시
4. 확대하거나 점에 마우스를 올리면 관계 이름이 뜨고, 선을 클릭하면 문장으로 설명

## 4. 라벨 노출 (progressive disclosure)

- 평소: 라벨 숨김 — 첫인상은 구조(뼈대)만.
- 확대(줌 ≥ 1.1) 또는 노드 hover(이웃 엣지) 또는 엣지 선택: 한국어 짧은 라벨("부분"·"선행"…)이 선 위에 등장.
- 엣지 클릭: 상세 패널에 방향이 녹아 있는 완전한 문장 — 예: `prerequisite` → "가상 메모리를 먼저 알아야 페이징을 이해할 수 있어요" (선수 개념 = target 이 문장 앞).
- strength/confidence 는 계약 §4.1/§4.2 구간 그대로 자연어("핵심 연결 · 근거 확실")로 병기한다.

필터 칩은 그룹 5개 단위이며 스와치(실선/점선·복습색)가 그래프 인코딩과 동일 — 칩이 곧 범례다.
