# OCR eval

이미지 → 3-block 아카이브 노트([`src/llm/ocr.ts`](../../../../src/llm/ocr.ts))의 **문자 정확도와 구조 준수**를 측정한다. 러너: `npm run eval:ocr`

```bash
export GEMINI_API_KEY=...
npm run eval:ocr                             # 전체 fixture
npm run eval:ocr -- --case printed-formula   # 하나만
npm run eval:ocr -- --dry                    # 배선만 확인
```

## 왜 단위 테스트가 아닌가

`ocr.test.ts`는 요청 모양(비전 메시지 구성)과 오프라인 폴백, 응답 파싱을 본다. **읽어낸 글자가 맞는지는 다루지 않는다.** 그건 실제 이미지와 실제 모델 없이는 잴 수 없다.

OCR 실패는 이진이 아니라 **정도**다. "O(log n)"이 "0(log n)"이 되거나 "이진"이 "이전"이 되는 것은 `toBe()`로는 그냥 실패지만, 실제로는 사용자가 고칠 수 있는 수준인지 아닌지가 갈린다. 그래서 문자 오류율(CER)로 본다.

## 판정 층

전부 코드다. judge 없음.

- **CER(문자 오류율)** — 정답 대비 편집거리 / 정답 길이. 0이면 완전 일치, 1이면 정답 길이만큼 틀렸다.
- **3-block 구조** — `buildOcrRequest`가 `## 원문` / `## 구조` / `## 요약` 세 블록을 지시한다. 헤딩이 3개 미만이면 위반이다.
- **한국어 여부** — 한국어 설정에서 영어로 답하면 위반. 단 `## 원문`은 이미지를 그대로 옮기는 블록이라 제외하고, **`## 구조`·`## 요약`의 서술만** 본다(아래 적대적 검증).

### CER 정규화 규칙

`cer(reference, hypothesis)`([`scripts/evals/core.ts`](../../../../scripts/evals/core.ts))는 양쪽을 **NFC 유니코드 정규화 → 소문자 → 연속 공백 1칸 → 앞뒤 트림** 한 뒤 편집거리를 잰다.

왜 정규화하는가: 한글은 조합형(NFD)과 완성형(NFC)이 코드포인트 수준에서 다르고, macOS 파일 경유 텍스트는 NFD로 오기도 한다. 정규화 없이 재면 눈에 보이지 않는 차이가 CER을 통째로 부풀린다. 공백·대소문자도 마찬가지다 — 줄바꿈 하나 차이로 게이트가 깨지면 지표가 노이즈를 재는 것이다.

정규화하지 **않는** 것: 구두점, 수식 기호, 숫자. 이것들은 OCR이 실제로 틀리는 지점이고 사용자에게 의미가 다르다.

### 인쇄체와 손글씨 임계값이 다른 이유

같은 잣대를 쓰면 둘 중 하나가 무의미해진다. 인쇄체는 폰트가 규칙적이라 잘 하는 모델이면 거의 완벽해야 하고, 여기서 CER 0.3이 나오면 심각한 회귀다. 손글씨는 사람마다 글씨체가 달라 최선의 모델도 오독이 남는다 — 손글씨 임계값을 인쇄체 수준으로 조이면 게이트가 상시 빨개져 아무도 안 보게 된다.

그래서 `kind` 필드로 fixture를 나누고 임계값을 따로 둔다: 인쇄체 `≤ 0.15`, 손글씨 `≤ 0.30`.

### 이미지가 없으면 실행 실패다

fixture의 `imageFile` 경로에 파일이 없으면 어댑터가 **throw한다.** 조용히 건너뛰지 않는다.

이유: 건너뛰면 `cases`가 0이 되고 `cerPrinted`는 `NaN`이 되며, 게이트를 "측정 대상이 없으니 통과"로 처리하는 순간 **0건 측정하고 초록불**이 된다. 그게 지표를 무력화하는 가장 흔한 방식이다. 러너 코어는 지표가 없거나 `NaN`이면 실패로 판정하고, 이미지 부재는 그 전에 `runFailed`로 먼저 잡힌다.

`runImageOcr`에도 같은 함정이 있다. 키가 없으면 throw하지 않고 `engine: "none"` 오프라인 폴백 마크다운을 돌려주는데, 그 폴백은 **헤딩 3개짜리 한국어**라 구조·언어 게이트를 그대로 통과한다. 그래서 `offlineFallback`을 별도 지표로 두고 0으로 막는다.

## 합격선

깨지면 러너가 `exit 1`.

| 지표 | 허용 |
|---|---|
| `runFailed` | 0 — 실행 실패 0 |
| `offlineFallback` | 0 — 오프라인 폴백 채택 0건 |
| `structureViolation` | 0 — 3-block 구조 위반 0건 |
| `emptyBlocks` | 0 — 빈 블록 0건 |
| `notKorean` | 0 — 한국어 비율 0.5 미만 0건 |
| `cerPrinted` | ≤ 0.15 — 인쇄체 CER ≤ 0.15 *(잠정, baseline 측정 후 확정)* |
| `cerHandwritten` | ≤ 0.30 — 손글씨 CER ≤ 0.30 *(잠정, baseline 측정 후 확정)* |

## 현재 결과 — `results/latest.json`

**실측 완료 — 게이트 전부 통과** (`gemini-2.5-flash`, 2026-08-02, fixture 2종·실제 이미지).

| 지표 | 실측 | 허용 |
|---|---|---|
| `runFailed` / `offlineFallback` / `structureViolation` | 0 / 0 / 0 | 0 |
| `emptyBlocks` / `notKorean` | 0 / 0 | 0 |
| `cerPrinted` | **0.0408** | ≤ 0.15 |
| `cerHandwritten` | **0.0465** | ≤ 0.30 |

인쇄체·손글씨 모두 임계값 안쪽이고, 손글씨가 인쇄체보다 나쁘지 않다 — 지금 모델의 실패는 자형이 아니라 수식 표기(`·`, `^`, 첨자) 쪽이다. 임계값은 **잠정값 그대로** 둔다: 표본이 2건뿐이라 여유가 실력인지 우연인지 아직 못 가른다.

이미지는 저작권 문제가 없는 것(직접 촬영·직접 작성)만 넣는다. 손글씨는 사용자가 태블릿에 직접 쓴 필기, 인쇄체는 맑은 고딕 렌더링이다.

## 적대적 검증

README의 합격선만 보고 "게이트를 전부 통과하면서 쓸모없는 출력"을 설계한 뒤, mock `run()`으로 확인했다. **여기서 지표 자체가 뒤집혀 있었다는 것이 드러났다.**

| 시도한 공격 | 게이트가 잡았나 | 조치 |
|---|---|---|
| `## 원문`만 정확히 채우고 `## 구조`·`## 요약`은 헤딩만 두고 비우기 | ⚠️ CER이 잡긴 했지만 **이유가 틀렸다** — 헤딩 3개라 `structureViolation 0`이고, CER은 오히려 **더 좋아졌다** | `emptyBlocks` 지표 추가 |
| (위 공격의 대조군) 3블록을 제대로 채운 **정상 출력** | ❌ **정상 출력이 더 나쁘게 채점됐다** — 공격 CER **0.4286** vs 정상 CER **2.6429** | CER 측정 범위를 `## 원문` 블록으로 교정 |
| 영어로 답하기 | ❌ **통과함** — `notKorean`이 `/[가-힣]/` 존재 여부만 봤다 | 한국어 **비율**(`koreanRatio`) 0.5 미만 위반으로 교체 |
| 키 없이 오프라인 폴백 마크다운 | ✅ `offlineFallback`이 잡음 | 없음 |

### CER이 재던 것과 재야 하는 것

`groundTruth`는 `## 원문` 블록의 내용인데 CER은 **출력 전체**와 대조하고 있었다. 구조·요약 블록의 글자가 전부 오류로 계산돼, 42자짜리 정답 기준에서 정상 출력의 CER이 **2.64**가 나왔다. 임계값 0.15는 **어떤 올바른 출력으로도 만족할 수 없는 값**이었고, 더 나쁜 것은 순위가 뒤집혔다는 점이다 — 블록을 비울수록 CER이 좋아지므로 게이트가 **불완전한 출력을 적극적으로 선호**했다. 오독 여부도 구별하지 못했다(정상 2.6429 vs O→0·이진→이전 오독 2.6905).

`## 원문` 블록만 재도록 고친 뒤 실측:

| 출력 | 이전(전체 대조) | 현재(원문 블록) |
|---|---|---|
| 정상 3-block | 2.6429 ✗ | **0.0000** ✅ |
| 오독(O→0, 이진→이전) | 2.6905 ✗ | **0.0476** ✅ (0.15 이내 — 고칠 수 있는 수준) |
| 빈 구조·요약 | 0.4286 ✗ | 0.0000 → `emptyBlocks 2`로 **잡힘** |

**임계값 0.15/0.30은 그대로 뒀다.** 바꾼 것은 "무엇을 재는가"이고, 동시에 `emptyBlocks` 게이트를 추가해 전체 엄격도는 올라갔다. 이제 CER은 README가 처음부터 주장하던 것("정답 대비 편집거리")을 실제로 잰다.

### 실측이 드러낸 오탐 2건 (2차 교정)

실제 이미지·실제 모델로 baseline을 재자 **모델 출력은 정상인데 게이트 2개가 깨졌다**(`emptyBlocks 2`, `notKorean 1`). 적대적 출력이 통과하는 것만 결함이 아니다 — **정상 출력을 벌주는 것도 같은 결함**이다. 여기서도 고친 것은 측정 범위이고 임계값은 건드리지 않았다.

| 지표 | 무엇을 재고 있었나 (오탐) | 무엇으로 바꿨나 |
|---|---|---|
| `emptyBlocks` | 블록 경계를 `^#{1,6}` **모든 헤딩**으로 잡았다. `## 구조` 아래에 `### 이진 탐색`으로 재구성하면 `## 구조`의 본문이 하위 헤딩 직전까지가 되어 빈 문자열이 된다 — **프롬프트가 지시한 올바른 출력**이 fixture 2건 모두에서 각 1건씩 잡혔다 | 블록 경계를 **최상위 헤딩**(문서에 나타난 최소 깊이)으로 한정. 하위 헤딩은 상위 블록의 본문으로 본다 |
| `notKorean` | `koreanRatio`를 **출력 전체**에 적용했다. `## 원문`은 이미지에 보이는 것을 그대로 옮긴 블록이라 영문 논문 캡처면 영문인 게 맞고, 거기에 LaTeX(`$\text{softmax}(QK^T/\sqrt{d_k})$`)까지 더해져 정상 출력이 **0.4750**으로 떨어졌다 | `## 원문`을 제외한 **서술 블록**(구조·요약)만, 수식(`$…$`)·인라인 코드를 걷어낸 뒤 잰다 |

같은 출력 텍스트에 교정 전/후 측정기를 각각 적용한 실측 (`results/` 의 baseline run):

| 출력 | `emptyBlocks` 전 → 후 | `koreanRatio` 전 → 후 | CER 전 → 후 |
|---|---|---|---|
| `handwritten-bigo` 정상 출력 | 1 → **0** | 0.7840 → **0.8554** | 0.0465 → **0.0465** (불변) |
| `printed-attention` 정상 출력 | 1 → **0** | 0.4750 ✗ → **0.6010** ✅ | 0.0000 → **0.0000** (불변) |

**CER은 자릿수까지 그대로다.** `originalBlock()`이 떼어내는 `## 원문` 블록의 범위가 두 측정기에서 동일하기 때문이고, 이것이 "측정 범위만 고쳤다"의 확인 조건이다 — CER이 움직였다면 원문 블록 측정을 건드린 것이다.

교정이 게이트를 무디게 만들지 않았는지 mock으로 재확인 (`--case printed-attention`, `## 원문`은 정답과 일치시켜 CER을 0으로 고정):

| 공격 | 결과 |
|---|---|
| 헤딩 3개만 두고 `## 구조`·`## 요약` 본문을 진짜로 비우기 | ✅ **잡힘** — `emptyBlocks 2` → `exit 1` (`structureViolation 0`, CER 0으로 다른 게이트는 전부 통과했다) |
| 서술까지 전부 영어로 쓰기 | ✅ **잡힘** — 서술 블록 `koreanRatio` **0.0175** → `notKorean 1` → `exit 1` |

**자동으로 못 잡는 것:**

- **`emptyBlocks`는 비었는지만 본다.** `## 요약`에 아무 말이나 한 줄 적으면 통과한다. 구조·요약이 원문을 제대로 반영했는지는 게이트가 보지 않는다 — 사람 표본 검수가 필요하다.
- **`## 원문`의 서술 언어는 아무도 안 본다.** 설계상 그렇다(원문은 옮겨 적는 블록이다). 원문 블록에 영어 요약을 지어 넣어도 언어 게이트는 침묵하고, 대신 CER이 잡는다.
- **하위 헤딩만으로 3-block을 흉내내면 빠져나간다.** `structureViolation`은 여전히 깊이를 가리지 않고 헤딩 개수만 세므로, `## 원문` + `### 구조` + `### 요약` 같은 출력은 최상위 블록이 1개인데도 "3개"로 통과하고 그 뒤 `emptyBlocks`·`notKorean`이 볼 서술 블록이 사라진다. 실측 fixture에서는 나온 적 없고, 개수 세기를 최상위로 조이면 `# 원문` + `## 구조`처럼 깊이가 섞인 정상 출력이 새 오탐이 되므로 그대로 뒀다.
- **표본이 2건이다.** CER 여유(0.0408 / 0.15)가 모델 실력인지 fixture 운인지는 fixture가 늘어야 갈린다.

## fixture 추가하기

`fixtures/<id>.json` 하나가 케이스 하나이고, 이미지는 `fixtures/` 기준 상대 경로다.

```jsonc
{
  "id": "printed-formula",
  "imageFile": "images/printed-formula.png",   // fixtures/ 기준 상대 경로
  "kind": "printed",                            // "printed" | "handwritten" — 임계값이 갈린다
  "groundTruth": "…이미지에 보이는 텍스트 그대로…",
  "whyHard": "이 케이스가 어떻게 함정인가"
}
```

- `groundTruth`는 `## 원문` 블록에 해당하는 **본문 텍스트만** 적는다. CER도 출력 전체가 아니라 `## 원문` 블록만 떼어 재므로 둘의 범위가 일치한다(아래 적대적 검증 참조).
- `kind`를 틀리게 붙이면 임계값이 뒤바뀐다. 손글씨를 `printed`로 넣으면 게이트가 상시 실패한다.

**좋은 fixture는 문자 집합을 섞는다.** 수식 기호(`O(log n)`, `Σ`, 첨자), 한글과 영어 혼용, 표, 흐린 촬영본. 깨끗한 한글 인쇄체만 넣으면 CER이 항상 0에 붙어 회귀를 못 잡는다.
