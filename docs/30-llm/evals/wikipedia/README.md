# 위키백과 정답지 실험

위키백과 문서를 앱에 순차 투입해, **위키백과 편집자가 이미 내려둔 판정**을 정답지로 개념 추출을 채점한다.

```bash
npm run wiki-collect -- --dir docs/30-llm/evals/wikipedia   # 수집 + 정답지
npm run wiki-exp     -- --dir docs/30-llm/evals/wikipedia   # 5라운드 투입 (GEMINI_API_KEY 필요)
npm run wiki-score   -- --dir docs/30-llm/evals/wikipedia   # 채점
```

## 왜 위키백과인가

기존 골든 케이스([`../generate/`](../generate))는 기대 개념을 **사람이 손으로 적은 것**이다. 무엇을 개념으로 볼지가 채점자 판단에 걸려 있어, "우리 기준이 맞는가"를 물을 수 없다.

위키백과는 그 판정을 수십 년간 사람 손으로 쌓아둔 라벨셋이다. 정답지 3종을 그대로 가져온다.

| 정답지 | 위키백과에서의 뜻 | 채점 대상 |
| --- | --- | --- |
| 본문 `[[링크]]` | "별도 문서 자격이 있다" | 개념이 될 자격 |
| 걸침 횟수 | 몇 개 문서의 본문에서 불렸나 | 반복 — 논리가 아닌 실측 |
| 리다이렉트 | "이 표기들은 같은 개념" | `normalizeTitle` dedup |

**`prop=links` 를 그대로 쓰면 안 된다.** 하단 틀(navbox)의 링크까지 딸려와 본문 660자짜리 문서가 링크 324개로 잡힌다. 정답지는 wikitext 본문의 `[[...]]` 만 센다(`wiki-collect.ts` `bodyLinks`).

## 앱과 같은 조건인가

`wiki-experiment.ts` 는 `importStore.buildInput` → `llmApply.applyLlmResult` 를 CLI 로 재현한다. 채점 로직을 복제하지 않고 `src/` 에서 그대로 import 한다 — `normalizeTitle`, `mergeDuplicateConcepts`, `promote`.

| 축 | 앱과 |
| --- | --- |
| 모델·프롬프트 | 같음 — `selectProvider("gemini")`, `GEMINI_MODEL` |
| 청킹 | 같음 — `chunkOpts()` 가 꺼져 있으면 `undefined` → `generateWikiStructured` 직행 |
| 출력 언어 | 같음 — localStorage 없으면 `"ko"`, 앱 기본과 동일 |
| `sourceIds` | 같음 — 백엔드는 `validate_wiki` 검증에만 쓰고 재계산하지 않는다 |
| **`promote` 의 `round`** | **다름 — 의도적.** 앱은 `generate.ts:148` 에서 `{ round: 0 }` 고정이라 시간이 흐르지 않는다 |

`mergeMarkdown`(병합 시 본문 결합용 2차 호출)은 부르지 않는다. `sourceIds` 와 개념 수에는 영향이 없다.

## 실측 — 2026-08-19, `gemini-3.5-flash`, 한국어 위키백과 5장

원자료: [`results/rounds.json`](results/rounds.json). 입력 본문은 커밋하지 않는다(CC BY-SA) — `wiki-collect` 를 다시 돌리면 `input/` 에 재생성된다.

### 개념 수가 입력 길이와 무관하다

| 라운드 | 문서 | 입력 | 개념 | 신규 | 병합 | 관계 | 본문링크 일치 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| R0 | 기계 학습 | 2,271자 | 4 | 4 | 0 | 3 | 50% |
| R1 | 인공 신경망 | 32,739자 | 8 | 7 | 1 | 9 | 100% |
| R2 | 딥 러닝 | 27,029자 | 9 | 9 | 0 | 8 | 11% |
| R3 | 순환 신경망 | 9,991자 | 7 | 6 | 1 | 11 | 14% |
| R4 | 트랜스포머 | 91,174자 | 9 | 9 | 0 | 7 | 11% |

91,174자에서 개념 9개 — 1만 자당 1개꼴이다. **노드 폭증이 아니라 추출 빈곤이다.**

### 반복 — 정답지 43개 중 우리가 2개

| | |
| --- | ---: |
| 위키백과 기준 2개 이상 문서에 걸친 개념 | 43 |
| 우리 `sourceIds` 2개 이상 | **2** / 총 33장 |

병합이 안 되는 1차 원인은 표기 변형이 아니라 **애초에 안 뽑아서**다. 「음성 인식」(5장 걸침), 「강화 학습」(4장), 「컴퓨터 비전」(4장), 「활성화 함수」(3장) 전부 미추출.

### dedup — 리다이렉트가 잡아낸 실패 2건

| 위키백과 판정 | 앱 결과 |
| --- | --- |
| 「순환 인공 신경망」 = 「순환 신경망」 | 2장으로 갈림 |
| 「딥 러닝」 = 「심층 신경망」 | 2장으로 갈림 |

병합에 성공한 2장은 표기가 **정확히 같았던** 경우뿐이다. `normalizeTitle` 은 NFC·소문자·공백만 정규화하므로 표기 변형을 잡지 못한다.

### 상태 머신 — 흐르게 해도 움직이지 않는다

| 라운드 | R0 | R1 | R2 | R3 | R4 |
| --- | ---: | ---: | ---: | ---: | ---: |
| active | 4 | 11 | 20 | 26 | 34 |
| staging | 0 | 0 | 0 | 0 | 1 |
| archived | 0 | 0 | 0 | 0 | 0 |

`round` 를 실제로 증가시켜도 staging 은 마지막에 1개(「어텐션 메커니즘」), archived 는 0이다. 개념을 적게 뽑고 LLM 이 관계를 대부분 붙여 주어 전부 `degree ≥ 1` 로 즉시 active 가 된다.

## 이 실험이 재지 못하는 것

- **근거 문장(`sourceRefs`)** — 전량 폐기된다. `buildInput` 의 `sourceFiles` 는 본문에 `![[파일]]` 임베드가 있을 때만 채워지는데(`llmApply.embedSourceFiles`), 위키백과 `.md` 에는 임베드가 없다. `sanitizeSourceRefs` 가 전부 버린다. 논문 대조군에서도 같았다 — 위키 28장 중 `sourceRefs` 를 가진 것 0장.
- **본문링크 일치율의 절대값** — R4 가 뽑은 `RoPE` · `ALiBi` · `FlashAttention` · `KV 캐싱` 은 한국어 위키백과에 문서가 없다. 일치율은 앱 품질만이 아니라 **한국어 위키백과 커버리지**를 함께 잰다. 라운드 간 비교로 읽으면 안 된다.
- **개체 배제** — 이 입력에서 개체 후보는 0개였다. 위키백과 문서에는 제품명이 잘 등장하지 않는다.

## 대조군

논문 5장(`Desktop/pp-test-docs-2026-08-12`, 2026-08-12 실측)에서는 위키 28장 · 관계 31건이 나왔고 `sourceIds` 는 27장이 1개, 1장이 2개였다. 그쪽에서는 고립 노드(`DeepSearchQA`, 관계 0)가 실제로 남았다.

**입력이 바뀌면 진단이 뒤집힌다.** 어느 한쪽만 보고 결론을 내면 안 된다.
