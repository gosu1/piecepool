# PiecePool 여정 기록 (Idea → Product)

아이디어가 제품이 되기까지의 **큰 사건만** 남기는 경량 로그. 보고서·사업 자료·PPT·아이디어 발전 과정 회고의 원재료로 쓴다.

> 규칙: 큰 변화(주요 기능·확정 결정·피벗)마다 표에 **한 줄** 추가. 기술 상세는 쓰지 않고 ADR/스펙 링크로 대신한다. "의미" 칸은 PPT 슬라이드에 그대로 옮길 수 있는 문장으로 쓴다.
> **누가 남기나**: 해당 PR **작성자(기여자) 본인**이 merge 전에 같은 PR 안에서 추가한다 — 누가 merge하든 기록이 함께 들어온다. 강제 장치 3중: PR 템플릿 체크리스트 · [CONTRIBUTING](../../CONTRIBUTING.md) 규칙 · **Claude Code 공유 훅**(`scripts/hooks/journey-guard.sh` — feat 커밋 PR인데 본 문서 변경이 없으면 `gh pr create` 차단). 사소한 변경(deps·오타·리팩터링)은 남기지 않는다.

## 1. 원점 — 문제와 아이디어

- **문제**: 강의 중 이해 속도가 진도를 못 따라간다 → 필기는 논리정연한 글이 아니라 **파편**(불릿·반문장·화살표)으로만 쌓인다. 파편은 복습 가치가 낮고, 버려진다.
- **아이디어**: 파편을 버리지 않는다. AI가 파편을 **개념 위키 + 지식 그래프 + 논리정연한 정리 글**로 재구성한다.
- **차별점 3가지**: ① 원본 불변 — 사용자의 필기는 절대 덮어쓰지 않는다(archive 계약) ② 근거 추적 — 모든 개념·관계가 출처(provenance)를 갖는다 ③ API 키 없이도 전 기능 동작(오프라인 폴백).

| 07-10 | **"새 노트"가 진짜 빈 노트로 열린다 + 마크다운 라이브 프리뷰** — 보조 패널(PDF·위키)의 열림 상태를 전역 저장하던 것을 노트 단위로 되돌리고 자동 선택 폴백(`?? existing[0]`) 제거, 새 노트마다 초안·패널·선택 초기화(미저장 초안은 확인 후 폐기). 에디터엔 태그별 HighlightStyle을 입혀 `#`를 치는 즉시 제목 크기가 바뀐다 | 빈 노트를 열었는데 남의 PDF와 무관한 위키가 양옆에 딸려 오던 첫인상 붕괴를 제거 — "새 노트"라는 말이 화면과 일치하게 됐다. 글쓰기 화면은 타이핑과 동시에 문서가 되고, 마크업 기호는 흐리게 남겨 저장되는 원문(archive)이 무엇인지 감춘 적 없다 |
| 07-10 | **데모 공간 3개(통계학·경제학·생리학)** — 기획서 그래프 목업을 실제 시드 데이터로 구현. 각 공간에 과목 2개를 두어 크로스 과목 엣지(회귀분석↔선형회귀, 한계비용←미분, 확산←농도 기울기)를 계약 위반 없이 표현. `seed/data.rs` 분리 | 기획서의 손그림이 실제 앱 화면이 됐다 — "전공을 넘어 개념이 이어진다"는 핵심 주장을 목업이 아니라 돌아가는 제품으로 증명한다. 공간을 넘는 엣지는 계약상 불가능하므로, 한 공간 안의 두 과목으로 표현하는 것이 정답임을 코드로 확정 |
| 07-10 | **파인만식 되묻기** — 선택지 클릭을 없애고 학생이 자기 말로 설명하게 한다. LLM은 구멍 하나만 짚어 되묻되 답을 주지 않고, 이해 판정은 오직 사용자([네, 이해했어요]/[아직 모르겠어요]). 후자는 `review_needed` self-loop로 기록돼 그래프에 빨간 점선 테두리로 뜬다. 행동 품질은 적대 시나리오 18종 eval(`npm run eval:feynman`)로 계측 | 기존 되묻기는 사용자가 쓴 문장을 그대로 선택지로 되돌려줘 '설명 깊이의 착각'(Rozenblit & Keil, 2002)을 오히려 **강화**하고 있었다. 착각을 깨는 유일한 방법은 직접 설명하게 시키는 것 — AI가 학생을 채점하지 않고 학생이 스스로 인정한다. '크고 빨간 테두리 = 중요한데 아직 설명 못 하는 개념'이 공짜로 드러난다 |
| 07-10 | **복습 표시 왕복 + 시드 출처** — 그래프 노드에서 되묻기 없이도 "아직 모르겠다"고 표시하고(이유가 곧 근거) 해제하고 다시 표시한다. 시드 위키에 원본 노트 출처(`sourceIds`)를 매달아 위키의 "관련 소스"·노트 하단 복습 바·그래프 표시가 모두 동작하게 했다 | "이건 아직 모르겠다"는 판단은 되묻기 안에서만 나오는 게 아니다 — 언제 어디서든 사용자가 선언하고 거둔다. AI는 이 표시를 만들지도 지우지도 못한다. 그리고 시드 데이터도 "모든 개념은 출처를 갖는다"는 원칙을 이제 지킨다 |
| 07-11 | **PDF 영어→한국어 번역·요약 스트리밍** — PDF 업로드 시 영어 목차만 뽑던 것을(구 `runOutline`), 원문을 한국어로 번역·요약한 학습 노트(`# 요약`+섹션별 정리+`> [!easy]` 쉬운 설명 접기+`$수식$`)로 노트 본문에 실시간 스트리밍. 결과는 유니브AI와 달리 **편집 가능한 마크다운**. 에디터는 노션식 수식 라이브 프리뷰(커서 닿으면 원문)·옵시디언식 콜아웃 접기, 초안을 스토어로 끌어올려 탭 전환에도 스트림·내용 보존 ([spec](../superpowers/specs/2026-07-11-pdf-korean-summary-design.md)) | 영어 논문 앞에서 얼어붙던 학생에게 "읽을 수 있는 한국어 요약"을 눈앞에서 만들어 준다 — 유니브AI의 결과물을 넘어 **사용자가 직접 고쳐 자기 노트로 만드는** 한 걸음. 원문(archive) 불가침은 지키되, 저장 전 초안은 사용자 소유라는 선을 지켰다 |
| 07-11 | **과목 선택을 "쓰는 자리"로 —전역 과목 바 제거 + 패널 안에서 대상 지정** — 사이드바 하단 볼트 스위처·StudyHome 하단 공간 목록(전역 과목 전환 UI)을 없애고, 대상 과목은 그 일을 하는 화면 안에서 고른다: Inbox는 저장 위치 드롭다운(커스텀 팝오버 + 거기서 바로 새 과목 폴더 생성, 바꾸면 위키 참조 패널도 그 과목을 따라감), Graph는 과목 칩(6개 넘으면 드롭다운)·전체 과목. 리본에 Inbox 버튼과 단축키 도움말(⌘W 탭 닫기 포함) 이관, 그래프 "복습" 칩은 표시한 개념만 남긴다 | 학생은 "지금 어느 과목 모드인가"를 기억할 필요가 없다 — 노트를 저장할 때 어디에 넣을지, 그래프를 볼 때 어느 과목을 볼지를 **그 순간 그 화면에서** 정한다. 전역 상태를 지우고 각 작업 화면이 자기 맥락을 소유하게 하니 조작 지점이 하나로 모이고(과목 폴더 생성까지 Inbox 안에서 끝난다), 사이드바는 파일 트리라는 본업만 남았다 |
| 07-11 | **Inbox = 웹 탭 모델(노트 하나 = 탭 하나) + 살아있는 노트** — "새 노트"가 공간별 단일 Inbox를 재활용해 옛 노트를 덮어쓰던 것을, 고유 id의 새 탭을 맨 끝에 append하고 X로만 닫히게 바꿈. 탭 전환·앱 재시작에도 작성 중이던 제목·본문·PDF·요약이 draft store(탭 id key, localStorage persist)로 보존되고, AI 정리(위키 생성) 후에도 노트가 사라지지 않고 이어서 필기한다(재저장은 새 파일 대신 같은 노트 갱신). #180 PDF요약·#181 퀵메모 위에 재통합 | 학생이 "저장하면 내 노트가 어디 갔지" 하고 원본 폴더를 뒤지던 흐름의 단절을 없앴다 — 학습이 일어나는 곳은 파일 캐비닛이 아니라 Inbox 하나이고, 무엇을 눌러도(탭 이동·저장·PDF 요약) 내 작업을 잃지 않는다. 여러 과목의 노트를 브라우저 탭처럼 나란히 두고 오가며 공부한다 |
| 07-11 | **섹션 단위 파인만** — 되묻기 대상을 노트 전체에서 `##`(제목2) 섹션으로 좁혔다. 에디터에서 헤딩이나 그 아래 글을 드래그하면 선택 위에 버튼이 뜨고, `##` 을 잡으면 하위 `###` 소주제까지 순차로, 소주제만 잡으면 그 하나만 설명하게 한다. 설명을 한 번도 안 하면 [이해했어요] 를 누를 수 없고, 판정은 기기 로컬에 남아 다음 단계(핵심 주제 게이트)의 근거가 된다. 노트 본문은 절대 변하지 않는다 | 노트 한 장을 통째로 "설명해보라"는 건 사실상 아무것도 묻지 않는 것과 같다 — 학생은 어디서부터 말해야 할지 모른다. 학생이 이미 손으로 나눠 놓은 경계(`##`)가 곧 주제의 경계이므로, 그 단위로 물으면 대답할 수 있는 크기가 된다. 되묻기가 "기능"에서 "공부하다가 막힌 그 자리에서 바로 쓰는 도구"로 내려왔다 |
| 07-11 | **워크스페이스 크롬 정리 + 손이 키보드를 떠나지 않는 에디터** — 경로만 보여주던 브레드크럼과 하단 상태바를 지우고 경로를 상태바 한 줄로 합쳐 화면 두 줄을 회수, 패널 토글(PDF·위키)은 패널이 열릴 때마다 가운데로 딸려오던 자리를 떠나 탭 바 우측에 고정. 서식 단축키(⌘B 굵게 · ⌘I 기울임)와 탭 이동(⌘Tab · ⌘⇧Tab)을 붙이고, `**`·`*` 마크업 기호는 커서가 닿을 때만 드러난다(수식·콜아웃과 같은 규칙). 마지막 탭을 닫으면 빈 화면 대신 Study Home 이 열린다 | 필기는 흐름이다 — 굵게 하나 넣으려고 마우스를 잡는 순간 그 흐름이 끊긴다. 기호를 숨겨 화면은 완성된 문서로 보이되, 커서를 대면 원문이 그대로 나타나 "무엇이 저장되는가"를 감춘 적이 없다(원본 불가침). 크롬이 줄어든 만큼 글이 늘었다 |
| 07-12 | **LLM 생성 언어 설정(ko/en) + 용어 혼용 규칙** — 설정 모달의 "생성 언어" 토글 하나가 위키·파인만·간극질문·PDF요약·정리글·OCR·휴리스틱 폴백 7개 생성 지점을 통제한다. 언어 규칙은 `src/llm/language.ts` 단일 SSOT: 원문에 나온 용어는 원문 표기 그대로, 없는 전문용어는 분야 관례를 따라 영어(process, deadlock)든 한국어(미분, 수요곡선)든 통용되는 쪽으로. 계약 2문서의 "한국어 1-2문장" 규정도 "언어 설정 따름"으로 개정(contracts-change). tidy는 제외 — 학생 문체 보존이 그 기능의 정체성 | "한국어로 써줘"가 곧 "process를 프로세스라 쓰라"는 뜻은 아니다 — 학생이 실제 시험장과 실무에서 만나는 표기를 그대로 배워야 한다. 언어는 사용자가 고르되 용어 관례는 시스템이 지켜, 번역투가 아닌 그 분야 사람이 쓰는 문체로 생성물이 나온다 |
| 07-12 | **원본은 노트에 종속된다** — 강의자료를 "공간의 자료실에서 골라 쓰는" 모델을 버리고 노트의 첨부물로 재정의. 노트 하나 = PDF 하나(고르기 UI 제거, 노트마다 업로드), 저장 폴더를 바꾸면 원본도 함께 이동(`move_source`), 저장 없이 탭을 닫거나 노트를 지우면 원본도 함께 사라진다. 삭제·이동 대상은 본문 파싱이 아니라 "이 초안이 올린 것"으로 한정해 남의 노트 파일은 건드리지 않는다 ([spec](../superpowers/specs/2026-07-12-note-owns-source-design.md)) | 학생은 파일을 관리하지 않는다 — 자료는 노트에 매달려 함께 움직이고 함께 사라진다. "그 PDF 어느 폴더에 있더라"를 물을 일이 없고, 노트를 다른 과목으로 옮겨도 옆에 띄운 강의자료가 따라온다 |
| 07-13 | **위키 본문 축적 — 프로토타입 A(LLM 통합 재작성)** — 같은 개념을 다른 노트에서 다시 만나면 위키 본문이 새 노트 것으로 통째로 덮이던 문제. 병합이 실제로 일어나는 개념에만 2차 LLM 호출(`src/llm/mergeWiki.ts`)을 걸어 기존 본문 + 새 내용을 한 편의 글로 통합한다. 실패·빈 응답·키 없음이면 기존 본문을 그대로 두고(출처·관계는 그래도 누적) 새 내용을 못 얹을지언정 쌓인 지식을 덮지 않는다. 기계적 덧붙이기 방식(프로토타입 B)과 실물로 비교해 고른다 | 위키는 노트 한 장의 요약이 아니라 **한 개념에 대해 학기 내내 자라는 글**이다 — 3주차에 다시 배운 내용이 1주차 필기를 지우는 게 아니라 같은 글에 얹힌다. 대신 LLM이 기존 문장을 다시 쓴다는 대가가 따르므로(사용자가 직접 쓴 문단까지 재작성될 수 있음), 두 방식을 실제로 굴려 보고 "원본 불가침"의 경계를 어디까지 위키에 적용할지 팀이 정한다 |
| 07-13 | **퀵메모 = 노트마다 하나** ([설계](../superpowers/specs/2026-07-13-quickmemo-per-note-design.md)) — 전역 키 하나에 살던 메모 원문을 노트 초안(`InboxDraft.memo`)으로 옮겼다. 다른 과목 노트로 옮겨 메모장을 켜면 직전 노트의 파편이 그대로 떠 있던 문제. 탭이 닫히면 메모도 함께 사라진다(`clear(key)`). 창 위치·크기만 전역으로 남는다 — 그것은 메모의 *내용*이 아니라 *창을 어디에 두고 싶은가* 라는 취향이다 | 퀵메모는 "지금 이 노트를 쓰기 위한 작업대"인데 데이터가 그렇게 모델링돼 있지 않았다 — 통계학 노트를 열었는데 어제 생리학 강의에서 갈겨쓴 파편이 떠 있으면, 그 순간 학생은 자기 작업 공간을 믿지 못하게 된다. 노트 하나 = 작업대 하나. 원본은 노트에 종속된다(07-12)와 같은 원리가 메모에도 적용됐다 |

| 07-14 | **지식 영역 폴더명 = 화면에서 본 이름** (계약 [workspace-layout §4](../10-contracts/workspace-layout.md) 변경) — 폴더명을 ASCII kebab slug 로 강제하던 규칙을 버렸다. `slugify` 가 비ASCII 를 통째로 버리는 탓에 "미적분학" 은 해시(`a3f19c2b`), "AI 딥러닝" 은 `ai` 가 되고 있었다. 이제 표시 이름을 그대로 폴더명으로 쓰고(경로 위험 문자만 치환), 이름을 바꾸면 디스크 폴더도 함께 옮긴다. archive/wiki **파일명**은 종전대로 ASCII 유지 — 바뀐 것은 지식 영역 **폴더**뿐 | 로컬 마크다운이 저장소라는 것이 이 제품의 약속인데, 정작 Finder 를 열면 자기가 만든 "운영체제" 가 `a3f19c2b` 로 보였다. 내 파일을 내가 못 알아보는 순간 "당신의 파일은 당신 것" 이라는 약속이 깨진다. 사용자가 붙인 이름이 곧 디스크의 이름이다 |

## 3. 아이디어 발전 과정 (PPT 스토리라인용 5막)

1. **문제 발견** — "필기가 파편으로만 남는다"는 학습자의 보편 문제에서 출발.
2. **구조 설계** — 코드 전에 계약(엔티티·관계 12종·파일 레이아웃)을 확정. 팀 4역할이 같은 언어로 말하게 됨.
3. **현실 피벗** — 로컬 LLM 실험 후 OpenAI 단일로 축소. "다 지원"보다 "하나를 제대로"가 대회 전략.
4. **지식의 품질 장치** — 시멘틱 청킹(의미 경계 분할) + 연결성 게이트(고립 노드 staging) + 출처 신뢰도(Liner) — 그래프가 쓰레기장이 되지 않게 하는 3중 장치.
5. **원점 회귀** — 마지막에 다시 첫 문제로: 파편을 **실시간 스트리밍**으로 정리 글로 바꿔 보여준다. 수집(Inbox) → 구조화(위키·그래프) → 재구성(정리 글)의 학습 루프 완성.
