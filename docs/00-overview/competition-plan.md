# 대회 제출 Plan (SW부문)

PiecePool로 출전하는 SW 경진대회 제출물·마감·역산 실행 계획. **팀 전원 필독**.

> 기준일 2026-05-29. 현재 코드 상태 = 컴파일되는 골격(IPC 스텁 1개 + [`entities`](../10-contracts/entities.md) 미러 models + ts-rs 타입 생성 + CI green), 실기능 0.
> MVP 범위는 [`scope-mvp.md`](scope-mvp.md) 참고. 본 문서는 그 범위를 **대회 마감에 맞춰 잘라낸** 실행 계획이다.

---

## 1. 마감 → 산출물 맵

| 단계 | 마감 | 필수 | 선택 |
|---|---|---|---|
| 예선 | **7.7 (화) 10:00** | ① 아이디어 기획서 | — |
| 예선 | **7.15 (수) 10:00** | ② 최종 산출물 (PDF) | 시연영상/데모버전 |
| 본선 | **7.20 (월) 10:00** | ① 전체 코드(ZIP, github 링크 대체) ② 데모버전 ③ 발표자료(PDF) | 시연영상 |
| 본선 | **7.30 (목) 10:00** | ④ 포스터 세션 자료(1장, 심사 X) | — |

규정 주의:
- 예선 ① 미업로드 = **본 대회 미참여 간주**. (절대 게이트)
- 예선 ② 미제출 = ① 아이디어 기획서로 **투표(예선 평가)** 진행.
- 본선 필수(①~③)는 본선 진출 후보팀까지 제출 요청될 수 있음.

---

## 2. 핵심 전략

- **예선 ①(7.7)이 생사 게이트.** 가장 쉽고 가장 치명적. 가장 먼저 끝낸다.
- **예선 평가 = 투표.** "선택"인 시연영상이 사실상 표를 가른다 → **필수 취급**.
- **본선 코드 = github 링크 대체** → 이미 `gosu1/piecepool` 푸시 중. 거의 공짜로 충족.
- 7.7까지 ~5.5주. 시간은 여유. 진짜 함정은 **과제작**: [`scope-mvp.md`](scope-mvp.md) 전체(OCR + LLM + Graph)를 다 만들려다 데모를 못 만든다.

---

## 3. 데모 핵심 경로 (단 하나만 완성)

대회용으로 **이 한 흐름만** end-to-end 완성한다 (seed 데이터 위에서 결정적으로):

```
PDF 드롭(Inbox)
  → Rust 텍스트 추출(pdf 모듈)
  → TS LLM adapter가 구조화 wiki 생성(Concept + WikiPage + Relation)
  → 파일/메타 저장
  → Wiki View 마크다운 + [[위키링크]] 렌더
  → Graph View 노드/엣지
```

이번 사이클 **컷(연기)**:

| 컷 항목 | 사유 |
|---|---|
| 이미지/필기 OCR | 데모 핵심 경로 밖. PDF 텍스트 추출로 대체 |
| prioritization / Question 생성 | 데모 설득력에 기여 낮음 |

근거: 예선은 투표다. 위 한 흐름이 깔끔하면 표를 이긴다. ([`relation-types.md`](../10-contracts/relation-types.md) 그래프가 시각적 임팩트 담당.)

## 4. 산출물 → 프로젝트 매핑

| 산출물 | 출처 / 작업 |
|---|---|
| 아이디어 기획서 | 거의 조립: [`vision.md`](vision.md) + [`scope-mvp.md`](scope-mvp.md) + [`entities`](../10-contracts/entities.md)/[`relation-types`](../10-contracts/relation-types.md). 문제→해법→아키텍처→범위→로드맵 |
| 최종 산출물 PDF | 데모 슬라이스 스크린샷 + 아키텍처(Tauri+Rust+React, ts-rs seam, TS LLM adapter) + seed 결과 리포트 |
| 시연영상 | §3 핵심 경로 화면녹화. seed 입력으로 결정적 |
| 본선 코드 | `gosu1/piecepool` 릴리즈 태그 + README 정리 + 빌드 확인. 신규작업 최소 |
| 데모버전 | `.app`/`.dmg` 빌드(scope-mvp §2.1). 공증은 함정 → 미서명 + Gatekeeper 우회 안내 우선 |
| 발표 PDF | 예선 문서 + 데모 재활용 |
| 포스터 1장 | 양식 채우기. 심사 제외, 저노력 |

## 5. 단계별 Plan (검증 게이트 포함)

1. **Phase 0 (~6/6) — 예선 게이트 잠금.** 아이디어 기획서 초안 완성.
   - 검증: 문제/해법/아키텍처/범위/로드맵 포함, 제출 가능 상태. *7.7 한참 전.*
2. **Phase 1 (6/6~6/27) — 데모 핵심 경로 end-to-end.**
   - 검증: PDF 1개 → wiki + graph 렌더, 크래시 0, `npm run tauri dev` 구동.
3. **Phase 2 (6/27~7/13) — 광 내기 + 영상 + 최종 PDF.**
   - 검증: 영상이 전체 흐름 시연; PDF에 스크린샷 + 아키텍처 + 결과.
   - **제출: 기획서 7/7, 산출물 + 영상 7/15.**
4. **Phase 3 (본선 진출 시, 7/15~7/20) — github 릴리즈 태그 + `.app`/`.dmg` + 발표 PDF.**
   - 검증: 깨끗한 환경에서 빌드 구동; 발표 리허설.
5. **Phase 4 (7/20~7/30) — 포스터 1장.** 양식 채우기.
