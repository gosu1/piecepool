# 그래프 계층 배치가 한 덩어리에서만 유지되는 문제

작성 2026-07-10. 조사 완료, 구현 대기. 열린 결정 2건 해소됨 (§6).

## 1. 증상의 정확한 정체

`untitled-3`(생리학) 워크스페이스, 계층 모드. 위키 노드 12개가 세 부류로 갈린다.

| 부류 | 개수 | `layerY` strength | 노드 |
|---|---|---|---|
| depth 있음 | 4 | **0.5** | 기관계(0) → 기관(1) → 조직(2) → 세포(3) |
| 엣지는 있으나 hier 엣지 없음 | 7 | **0** | 확산 · 부교감신경 · 교감신경 · 글루카곤 · 고혈당 · 농도 기울기 · 인슐린 |
| 완전 고립 (deg 0) | 1 | 0.12 (하단 밴드) | 삼투 |

사용자가 본 "하나의 묶음"은 `part_of` 4연쇄다. 나머지 7개는 세로 구속이 **문자 그대로 없다**.

```ts
// src/lib/CytoscapeGraph.tsx:97
.strength((d) => depth.has(d.id) ? 0.5 : (deg.get(d.id) ?? 0) === 0 ? 0.12 : 0)
//                                                                        ^^^ 중간군
```

`computeDepth`(`relationMeta.ts:108`)는 `part_of`·`prerequisite` 엣지가 닿은 노드만 Map 에 넣는다. 나머지는 `depth.has()` 가 false → strength 0.

## 2. 원인 분해 (검증된 순서)

### R1 (주범) — 계층 커버리지가 낮다

실측 (대칭 dedup 적용 후):

| 워크스페이스 | 위키 노드 | depth 받는 노드 | hier 엣지 | **비계층 엣지가 계층 노드에 닿는 수** |
|---|---|---|---|---|
| `untitled-3` | 12 | 4 (33%) | 3 | **0 / 4** |
| `untitled-2` | 12 | 4 (33%) | 3 | **0 / 5** |
| `untitled` | 17 | 8 (47%) | 6 | 9 / 11 |

`untitled-2`·`untitled-3` 에서 **계층 사슬은 나머지 그래프와 완전히 분리된 섬이다.** 비계층 엣지가 계층 노드에 하나도 안 닿는다.

이 사실이 해결안 두 개를 즉사시킨다. "이웃의 depth 를 전파해서 중간군에 soft depth 를 준다"는 접근(harmonic interpolation, BFS relaxation)은 이 데이터에서 **노드 0개**에 도달한다. 유닛테스트는 초록인데 증상은 그대로다.

### R2 (근본) — 이 데이터는 트리가 아니다

`untitled-3` 의 비계층 엣지 4개:

```
인슐린 --solves--> 고혈당
농도 기울기 --causes--> 확산
인슐린 --contrasts--> 글루카곤      ← 대칭. 대등하다.
교감신경 --contrasts--> 부교감신경   ← 대칭. 대등하다.
```

`contrasts` 는 계약상 **대칭**이다(relation-types.md §7.1). 대칭 쌍을 서로 다른 높이에 놓으면 "한쪽이 더 기초"라는 거짓 주장이 된다. `causes` 는 극성이 반대다 — "A가 B를 유발"에서 target(결과)을 위로 올리면 결과가 원인보다 기초라고 말하게 된다.

`untitled` 에서 가장 많은 관계는 `used_in` 8개다. 계약상 `used_in`("A가 B 안에서 활용됨")과 `part_of`("A는 B의 구성 요소")는 **조작적으로 구별이 안 된다** — 둘 다 Concept→Concept, 둘 다 B가 더 큰 맥락, 계약의 예시조차 같은 Transformer 앵커를 쓴다. 그런데 레이아웃은 둘을 정반대로 취급한다(하나는 계층축, 하나는 depth 없음).

**즉 이건 "레이아웃이 계층을 렌더 못 함"이 아니라 "대체로 대등한 연관 네트워크에 작은 국소 part-of 사슬이 몇 개 박혀 있음"이다.**

### R3 — 오버레이가 거짓말한다

`GraphSection.tsx:373` "그래프 읽는 법" 첫 줄:

> · 위에 있을수록 기초·전체 개념, 아래로 갈수록 세부예요

`untitled-3` 에서 12노드 중 8노드(67%)에 대해 거짓이다. force 모드에서는 세로축이 radial 이라 100% 거짓인데 문구는 그대로 뜬다. 첫 방문 시 자동으로 펼쳐진다.

### R4 (부차) — 계층이 있어도 흔들린다

- `layerY` strength 0.5 는 `forceLink` strength 0.4 와 같은 자릿수다. 부동 이웃 두셋이 링크로 매달리면 계층 노드가 제 층에서 끌려 내려온다. `untitled` 처럼 다리 엣지가 9개면 실제로 발생한다.
- d3-force 의 alpha 냉각은 `layerY` 를 포함한 **모든 힘을 0으로 끈다.** warm 구간에 밀려난 위치가 그대로 동결된다. 계층은 "자가 회복"하지 않는다 — graph-view.md §2 가 약속한 것과 다르다.
- `layerGap = min(110, max(70, h*0.76/maxDepth))`. `maxDepth` 가 3이면 상한 110 에 걸려 계층 전체가 화면 상단 좁은 띠에 눌린다.

### R5 (잠재, 지금 증상의 원인 아님) — `computeDepth` 비결정성

사이클이 있을 때 back-edge 절단이 DFS 시작 순서(= 엣지 배열 순서)에 의존한다. `state===2` 메모가 과소평가된 depth 를 영구 고정한다.

**단, 실제 데이터 세 곳 모두 hier 서브그래프에 사이클이 0개다.** 잠재 결함이지 현 증상의 원인이 아니다. 조사 중 이 둘을 혼동한 분석이 있었으나 데이터로 반박했다. 별도 correctness PR 로 다룬다.

## 3. 설계 원칙

이 앱의 자기 원칙은 반(反)날조다 — "없는 걸 있는 척하지 않는다"가 복습 표시·출처 처리 두 곳에 명시돼 있다. 대등한 개념에 세로 계층을 씌우는 것은 그 원칙 위반이다.

따라서 **없는 계층을 지어내지 않는다.** 대신 "위치가 의미를 갖는 노드"와 "안 갖는 노드"를 사용자가 구분할 수 있게 만든다.

## 4. 계획

### 0단계 — 검증 하네스 먼저 (없으면 "고쳤다"가 반증 불가능)

시각 배치는 자동 테스트가 어렵다는 이유로 지금까지 아무 테스트가 없다. 하지만 가능하다:

- `d3-force` v3 에 `simulation.randomSource(fn)` 이 있다(`node_modules/d3-force/src/simulation.js:121`). `jiggle` 의 `Math.random` 을 시드 RNG 로 갈아끼우면 시뮬이 **완전 결정적**이 된다. 초기 배치는 원래 phyllotaxis 나선이라 RNG 를 안 쓴다.
- `~/PiecePool/untitled-3/relations/relations.json` + wiki 목록을 픽스처로 복사.
- `buildSim` 을 순수 함수로 뽑아 시드 RNG + 고정 tick 수(예: 300)로 돌리고 좌표를 단언.

Pass condition (픽셀 골든이 아니라 **의미 단언**):

| # | 단언 |
|---|---|
| 1 | 계층 4노드의 y 가 depth 순서로 단조 증가 (기관계 < 기관 < 조직 < 세포) — **냉각 완료 후** |
| 2 | 각 계층 노드의 y 가 `topY + depth*layerGap` 에서 ±`layerGap*0.25` 이내 |
| 3 | 부동 7노드의 y 가 계층 밴드와 겹치지 않는다 (3단계 채택 시) |
| 4 | 엣지 배열을 셔플해도 1·2 가 동일 (결정성) |

**1번이 핵심이다.** 지금 코드로 돌리면 `untitled` 픽스처에서 실패해야 정상이다(링크 줄다리기 + 냉각 동결). 먼저 실패를 확인하고 진행한다.

### 1단계 — 정직 (가장 싸고 가장 가치 있음)

- `GraphSection.tsx:373` 오버레이 첫 줄을 `layoutMode` 와 hier 커버리지로 조건화. force 모드거나 커버리지가 낮으면 "위=기초" 줄을 빼거나 "일부 개념만 계층으로 배치돼요"로 교체.
- 계층 모드에서 depth 없는 노드를 시각적으로 구분(예: 테두리 점선, 또는 미묘한 채도 차). "이 노드의 세로 위치는 의미 없음"을 말한다.

계약 영향: `docs/40-frontend/graph-view.md` §3 문구 갱신. `docs/10-contracts/` **무변경** → 오너 4명 승인 불필요.

### 2단계 — 있는 계층은 확실히 고정 (신규 의존성 0)

- **`fy` 하드핀.** 계층 노드는 `layerY` 힘 대신 `node.fy = topY + depth*layerGap` 로 고정한다. 링크 줄다리기와 alpha 냉각 양쪽에 면역이 된다. 드래그 시작 시 핀 해제, 놓으면 재핀 → graph-view.md 가 약속한 "출렁이다 놓으면 제 층으로 복귀"가 **비로소 실제로** 성립한다. 가로(x)는 물리에 맡긴다.
- `layerGap` 상한 110 을 완화해 `maxDepth` 가 작을 때 화면 높이를 쓰게 한다.

이것이 dagre 를 넣지 않고도 dagre 안의 유일한 핵심(정적 y 고정)을 얻는 방법이다. hier 컴포넌트가 4·6·2 노드 규모라 Sugiyama 의 교차 최소화·network-simplex 는 요청하지 않은 유연성이고, `@dagrejs/dagre` 는 gzip 40~50KB 짜리 첫 순수 레이아웃 런타임 의존성이 된다. 기각.

### 3단계 — 부동 노드를 어디에 둘 것인가 (**결정 필요, §6-A**)

권장안: **"미순위 영역"으로 분리.** `layerY` strength 를 중간군에 대해 0 → 약한 값(≈0.08)으로 주고, target 은 이미 코드에 있으나 죽어 있는 `topY + (maxDepth+1)*layerGap` 를 살린다. deg 0 노드는 한 층 더 아래.

```ts
// 지금: depth 없으면 deg 0 만 하단으로, 나머지는 strength 0
// 제안: 중간군도 계층 밴드 아래 "네트워크 영역"으로 약하게
```

효과: 위쪽은 계층, 아래쪽은 연관 네트워크. **depth 를 지어내지 않으면서** 일관성 없는 인상을 없앤다. 변경량 사실상 1~2줄.

대안은 §6-A 에 정리.

### 4단계 (별도 트랙) — 상류

`gemini.ts:144` 의 배포 프롬프트에는 **관계 타입 지침이 한 줄도 없다.** LLM 이 받는 유일한 신호는 JSON Schema 의 enum 12개 문자열 나열뿐이다. `docs/30-llm/prompt-templates.md` §2/§5 의 지침은 코드에 하나도 구현돼 있지 않다.

큰 지렛대지만 상한이 있다. 같은 문서 §2·§5 가 "억지로 채우지 않는다 / 애매하면 관계를 만들지 않는다"를 계약으로 못박고 있어서, 원문이 평면적이면 hier 비율은 못 올린다. 또 `used_in`↔`part_of` 경계가 계약 수준에서 모호한 것이 근본 문제라, 프롬프트만으론 안 풀린다.

이 PR 범위 밖. 별도 이슈.

### 5단계 (별도 correctness PR) — `computeDepth` 결정성

Tarjan SCC 축약 → 응축 DAG longest-path. O(V+E), 순서 무관, 같은 SCC 는 같은 depth("상호 의존 = 같은 층", 정직한 표현). 순수 함수라 완전 유닛테스트 가능.

`relationMeta.test.ts:105` 의 사이클 테스트는 2노드 1개뿐이고 절대 차이만 검사한다. 엣지 순서 셔플 불변성 property 테스트를 추가한다.

현 데이터에 사이클이 없으므로 증상과 무관하다. **레이아웃 변경에 번들하지 말 것** — 검증 가능한 수정을 검증 어려운 수정에 사슬로 묶으면 둘 다 못 믿게 된다.
