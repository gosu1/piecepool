# PDF 원샷 파이프라인 + 본문 키워드→위키 — 설계

**날짜**: 2026-07-16 · **상태**: 설계 승인 (`worktree-feat-pdf-wiki-terms`, base `origin/main` 666c253)

## 배경 (왜)

piecepool 은 대학생 학습 보조 도구고, PDF 는 대부분 수업 교재다. 현재 흐름은 반쪽 자동이다:
PDF 드롭 → 원본 저장·텍스트 추출·한국어 요약 스트리밍까지는 자동이지만, **위키(개념) 생성은
"저장 + AI 정리" 버튼을 눌러야** 시작된다. 생성된 위키 탐색도 `PaneSelect` 드롭다운에서 하나씩
골라 보는 구조라 "이 교재에서 배울 키워드 전부"가 한눈에 안 보인다.

원하는 경험: **PDF 를 넣으면 요약과 위키가 전부 자동으로 나오고**(로딩 화면 표시), 학습 키워드가
위키 패널에 목록으로 다 뜨며, **본문 속 키워드가 은은히 강조되어 클릭하면 해당 위키가 패널에 뜬다.**

## 확정 결정 (사용자 승인)

1. **원샷 자동 파이프라인** — 요약 완료 시 자동으로 저장 + 위키 생성까지. 클릭 0회.
   노트 제목은 드롭 시 **모달로 입력**받는다(기본값 = PDF 파일명, 초안 제목 있으면 그 값).
2. **위키 패널 기본 화면 = 개념 목록** — 이번 노트에서 생긴 위키 전부. 드롭다운 제거.
3. **키워드 강조 적용 범위 = 전부** — Inbox 에디터 + DocView 읽기/편집 모드.
4. **접근 = 표시-시점 매칭** (프론트 전용, 본문 비파괴). 기각한 대안: LLM 이 요약에 앵커
   삽입(요약이 위키보다 먼저 나와 불일치·출력 불안정), 위키 생성 후 본문 재작성(사용자
   원문을 기계가 덮어씀 — archive 불가침 계약 위반 소지, `[[..]]` 는 원본 파일 링크라 의미 충돌).

## §1 원샷 파이프라인 + 제목 모달

트리거: Inbox 에 PDF 드롭/선택 (`InboxSection.importPdf`).

1. **제목 모달** — 입력 기본값 = 파일명(확장자 제거), 초안에 제목 있으면 그 값.
   Enter/확인 → 파이프라인 시작. 취소 → no-op(업로드 자체 취소).
2. 원본 저장(`saveSourceFile`) → `![[..]]` embed 삽입 → PDF 패널 자동 오픈 →
   텍스트 추출(`extractPdfText`) — 현행 그대로.
3. 요약 스트리밍(`inboxDraftStore.runSummary`) — 현행 그대로 본문에 병합.
4. **신규**: 요약이 `done` 이면 자동으로 기존 저장 루틴(`useImportStore.runImport`,
   `withLlm: true`) 호출 → `archiving → llm_processing → writing → completed`.
   노트는 모달 제목으로 archive 에 자동 저장되고 living note 로 바인딩(기존 동작 재사용).
5. `completed` 시 위키 패널 자동 오픈 — §3 목록 뷰부터.

**자동 저장을 하지 않는 경우** (부분 결과 유지, 현행 수동 흐름으로 폴백):

- 요약 `cancelled`(사용자 취소) / `failed` — 부분 텍스트는 본문에 유지.
- Gemini 키 없음, 스캔본(추출 텍스트 0) — 원본 저장 + embed 까지만 하고 안내(현행 유지).

**MVP 한계(명시)**: 요약 진행 중 Inbox 탭을 떠나면(컴포넌트 언마운트) 자동 저장 트리거가
끊긴다. 요약 텍스트는 스토어가 계속 받아 본문에 병합하므로 돌아와서 수동 저장하면 된다.

"저장 + AI 정리" 버튼은 유지 — 텍스트 노트·재저장용.

## §2 로딩 표시

새 컴포넌트 없음. 기존 `LoadingOverlay` 체인 연결만:
① PDF 저장·추출(pdfBusy) → ② AI 요약 스트리밍(라이브 텍스트) → ③ 저장+위키 단계
체크리스트(job 상태 기반). 저장 버튼은 전 구간 disabled(기존 게이트).
`feat+loading-quotes` worktree 가 오버레이 문구 작업 중이므로 **`LoadingOverlay` 자체는
수정하지 않는다** — 충돌 회피.

## §3 위키 패널 — 개념 목록 기본 화면

- `ImportJobView` 에 `wikiPaths: string[]` 추가 — 이번 임포트로 생성/병합된 위키 경로
  전부(`applyLlmResult` 의 `applied.pages` 에서, 지금은 개수만 기록). localStorage persist 포함.
- 패널 두 상태:
  - **목록 뷰(기본)**: 선택된 위키 없을 때. 바인딩된 노트의 완료 job 에 `wikiPaths` 있으면
    "이 노트의 개념" 목록, 없으면 공간 전체 위키 목록(폴백). 클릭 → 열람 뷰.
  - **열람 뷰**: 기존 그대로(제목 + `Markdown` 렌더) + "← 목록" 버튼.
- `PaneSelect` 드롭다운 제거.
- 임포트 `completed` 시 패널 자동 오픈, **목록 뷰부터**(기존 `firstWikiPath` 자동 선택 대체).

## §4 본문 키워드 강조·클릭

- **매칭 대상**: 대상 공간의 **모든 위키 제목**(이번 임포트분 포함) — 옛 노트에서도 일관 동작.
- **공유 매처 `src/lib/wikiTerms.ts`(신규)** — 에디터·렌더러가 같은 규칙:
  - 대소문자 무시, 겹치면 최장 일치 우선. 제목 2글자 미만 제외(과매칭 방지).
  - 경계: 매치 앞뒤가 영숫자/한글이면 불인정. 단 **한국어 조사 허용** — 제목 뒤에 붙은
    조사는 매치 인정("프로세스는" → "프로세스"). 조사 whitelist 는 `wikiTerms.ts` 상수로
    확정: 은 는 이 가 을 를 의 에 로 와 과 도 만 에서 부터 까지 처럼 조차 마저 (+ 이/그
    복합형은 불필요 — 단순 접미 매칭, 테스트로 고정).
  - 제외 구역: 코드블록·인라인코드, `[[..]]`/`![[..]]` 내부, URL. 헤딩은 포함.
- **에디터(Inbox + DocView 편집 공용)**: CodeMirror `ViewPlugin` + `Decoration.mark`
  (기존 `hideMarkupMarks` 패턴). 스타일 = 은은한 배경 틴트 + 점선 밑줄, hover 진해짐.
  **일반 클릭 = 커서 이동 + 위키 열림 동시** — 수식키 없음(패널이 옆에 떠 편집 흐름 유지),
  드래그 선택은 무시.
- **읽기 모드(DocView)**: remark 플러그인 `remarkWikiTerm` — 텍스트 노드의 매치를
  `term:` 링크로 변환, 기존 `wiki:`/`embed:` 스킴 패턴으로 렌더러에서 클릭 span 처리.
- **클릭 동작**: Inbox → 위키 패널 오픈 + 해당 위키 열람 뷰. DocView → 기존 `onLink`
  내비로 해당 위키 문서 이동.
- 본문 텍스트는 어떤 경우에도 수정하지 않는다(표시 계층 전용).

## §5 에러 처리

- 제목 모달 취소 → no-op. 원본 저장/추출 실패 → 기존 notice, 파이프라인 중단.
- 요약 취소·실패 → 자동 저장 안 함(§1), 수동 저장 폴백.
- `runImport` 실패 → 기존 failed 오버레이·에러 라벨. archiving 이후면 노트는 저장돼 있고
  바인딩 유지.
- 위키 생성 실패 → 기존 휴리스틱 폴백(`engine: "heuristic"`) — 목록 뷰엔 휴리스틱 개념이 뜬다.
- `wikiPaths` 없는 옛 job → 목록 뷰의 공간 전체 폴백이 자연 처리.
- 매처: 위키 0개면 no-op.
