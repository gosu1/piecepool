# Facet 커버리지 판정 — 설계 (v1)

이해지표(그래프 안개)의 심장 부품. 사용자의 파인만 설명을 WikiPage의 핵심 요점(facet)과 **대조만** 하여 다룸/부분/간극/어긋남을 돌려준다. **품질 채점은 하지 않는다** — "LLM은 채점하지 않는다"(파인만 원칙)를 유지하는 것이 이 설계의 존재 이유다.

> 맥락: 이해지표는 시스템이 상태를 계산(판결 엔진)하되 사용자에겐 거울로 보여준다("이 영역이 흐리다"). 굿하트 방어 원칙 = **레벨을 올리는 조건 자체가 진짜 이해 행위**여야 한다.

---

## 1. 전체 구조 — 2단 파이프라인

```
[위키 저장/갱신 시 · 위키 버전당 1회, 캐시]
WikiPage 본문 ──(프롬프트 A)──▶ facet 목록 { text, kind }[]
                                      캐시 키 = hash(위키 본문)

[파인만 설명 제출 시 · 설명당 1회]
facet 목록 + 사용자 설명 ──(프롬프트 B)──▶ 요점별 판정 { id, status, evidence }[]

[TS 레이어 · 결정적 코드]
Ajv 검증 → evidence 원문 대조 → 상태 전이 계산
```

2단으로 나누는 이유:

1. **비용** — 추출은 위키 버전당 1회. 설명 제출마다 위키 전문을 다시 읽히지 않는다.
2. **투명성(거울)** — facet 목록이 실재하므로 노드 클릭 시 "위키의 이 요점들"을 그대로 보여줄 수 있다. 숨은 채점 기준이 없다.
3. **판정 안정성** — 판정이 "긴 문서 이해"가 아니라 "짧은 목록 대조"가 되어 gemini-2.5-flash로도 흔들림이 적다.

## 2. 프롬프트 A — facet 추출

```text
당신은 학습 도구의 내부 부품이다. 아래 위키 문서에서, 이 개념을 진짜
이해한 사람이라면 자기 말로 표현할 수 있어야 하는 핵심 요점(facet)을
추출한다.

규칙:
1. 요점은 5~9개. 문서가 짧으면 3개까지 허용한다. 3개를 만들 수 없으면
   빈 배열을 반환한다.
2. 각 요점은 원자적이다 — 한 요점에는 정확히 하나의 사실/원리만 담아,
   어떤 설명이 그것을 다뤘는지 독립적으로 판정할 수 있어야 한다.
3. 반드시 아래 문서에 실제로 있는 내용만 쓴다. 문서에 없는 지식을
   보태지 않는다.
4. 각 요점은 "~다"로 끝나는 완결된 한 문장으로 쓴다.
5. kind는 하나를 고른다: definition(무엇인가) | mechanism(어떻게 동작하나)
   | rationale(왜 필요한가) | boundary(무엇과 다른가·한계)
   | connection(다른 개념과의 관계) | example(대표 사례)
6. 문서의 서식·링크·파일 경로·메타데이터는 요점이 아니다.
7. JSON만 출력한다.

[위키 문서]
{{wiki_body}}
```

- 출력 스키마: `{ "facets": [{ "text": string, "kind": enum6 }] }`
- **id는 LLM이 아니라 TS가 부여**한다(f1, f2, …). LLM에게 id 관리를 시키면 흔들린다.
- 규칙 2(원자성)가 전체 설계의 열쇠 — facet이 원자적이면 커버리지 판정이 거의 이진 판정이 되어 주관성(=채점 느낌)이 줄어든다.

## 3. 프롬프트 B — 커버리지 판정

```text
당신은 채점자가 아니다. 당신의 유일한 임무는, 사용자가 자기 말로 쓴
설명이 아래 요점 각각의 '의미'를 담고 있는지 대조하는 것이다.

절대 규칙:
1. 품질을 평가하지 않는다. 문체·길이·정확한 용어·맞춤법은 판정과
   무관하다. 요점의 의미가 어떤 표현으로든 담겨 있으면 covered다.
2. 자기 말 환언을 정답 표현과 동등하게 인정한다. 비유·구어체·서툰
   표현도 의미가 맞으면 covered다.
3. 점수·총평·칭찬·비판·조언을 출력하지 않는다. 요점별 판정만 출력한다.
4. status는 4가지다:
   - covered: 요점의 핵심 의미가 설명에 있다
   - partial: 언급했지만 핵심의 절반 이하만 담았다
   - missing: 설명에서 이 요점을 찾을 수 없다
   - contradicted: 설명이 이 요점과 명백히 반대되는 주장을 한다
5. covered / partial / contradicted에는 반드시 evidence를 붙인다 —
   사용자 설명에서 한 글자도 바꾸지 말고 그대로 옮긴 인용(최대 한 문장).
   missing은 evidence를 null로 둔다.
6. contradicted는 명백한 의미 충돌만이다. 애매하면 partial 또는
   missing으로 둔다.
7. 사용자가 요점 밖의 내용을 말했더라도 무시한다. 사용자의 의도를
   추측으로 보완하지 않는다.
8. JSON만 출력한다.

[요점 목록]
{{facets — "f1. (definition) 가상 메모리는 …다" 형식의 번호 목록}}

[사용자 설명]
{{explanation}}
```

- 출력 스키마: `{ "judgments": [{ "id": string, "status": enum4, "evidence": string|null }] }`
- 규칙 5(verbatim 인용)가 진짜 방어선 — LLM judge 최대 실패 모드인 "친절한 환각"(없는 커버리지를 후하게 인정)을 기계 검증으로 잡는다.
- 규칙 6 — contradicted(어긋남)는 가장 값진 신호(오개념 발견)이자 오판 시 가장 신뢰를 깨는 신호. 문턱을 명시적으로 높인다.

## 4. TS 레이어 가드레일 (LLM을 못 믿는 부분은 코드로)

1. **Ajv 스키마 검증** — draft 2020-12, `validate.ts`의 `LlmWikiResult` 검증과 동일 패턴. judgments의 id 집합이 입력 facet 집합과 정확히 일치하는지 TS가 추가 검사(스키마로 못 잡음). 불일치 → 1회 재시도 → 실패 시 판정 폐기.
2. **evidence 원문 대조** — 공백 정규화 후 사용자 설명 내 substring 검사. 인용이 실제로 없으면 해당 facet을 **missing으로 강등**.
3. **위키 복붙 감지** — 설명↔위키 본문의 문자 3-gram Jaccard > 0.6이면 승급 보류 + "자기 말로 다시 써볼까요?" 넛지용 플래그 반환. LLM 없이 TS만으로.
4. **상태 전이는 전부 결정적 코드** — LLM은 요점별 status만. 정책은 상수 한 곳에:
   ```ts
   // 튜닝 대상 상수 — 한 파일에 모은다
   clearScore = (covered + 0.5 * partial) / total
   CLEAR_OK   = clearScore >= 0.6 && contradicted === 0
   ```
   스칼라 점수는 어디에도 저장·표시하지 않는다. 저장은 judgments 배열 + 파생 상태뿐.
5. **실패 시 fail-closed** — API 다운·파싱 실패·검증 실패 전부 → 상태 불변(안개 유지). 원칙: *지표가 거짓으로 맑아지는 것이 최악이다.* 낙관적 승급 금지.

## 5. 엣지 케이스

| 상황 | 처리 |
|---|---|
| 설명이 너무 짧음("몰라") | TS 사전 체크(최소 글자 수, 예: 20자) → LLM 호출 없이 전부 missing |
| 위키가 스텁(facet < 3) | 커버리지 비활성 — 이 개념은 '연결' 신호로만 승급 |
| 한국어 설명 + 영어 용어 혼용 | 프롬프트 B 규칙 1·2가 커버 |
| 사용자가 위키보다 많이 앎 | v1 무시(규칙 7). v2에서 "위키에 추가할까요?" 역제안 |
| 동일 설명 재제출 | 텍스트 해시 디바운스, 재호출 안 함 |
| contradicted 발생 | 승급 차단 + 간극 최우선 표시. 표현은 오류 선고가 아니라 확인 요청 |

## 6. 평가 계획 (구현 후)

- RAGAS는 부적합(RAG Q&A용). 자체 골든셋: seed 위키 × 설명 5유형(충실/부분/오개념/위키 복붙/딴소리) ≈ 30~50건, facet별 사람 라벨 → judge 일치율. `npm run eval:coverage` (eval:feynman 패턴).
- 기준: **contradicted는 precision 우선**(억울한 '틀림'이 신뢰 파괴 최악), missing은 recall 관대 허용.
