# 퀵메모 = 노트마다 하나 (설계)

날짜: 2026-07-13
관련: [Quick Memo 최초 설계](2026-07-11-quick-memo-design.md), #183 노트=탭 모델

## 문제

퀵메모 원문이 전역 키 하나(`localStorage["quickmemo-draft"]`)에 산다. 다른 과목의 다른 노트로
옮겨 퀵메모를 켜면 **직전 노트에서 쓰던 파편이 그대로 떠 있다.** 지금 쓰는 글과 아무 관계가 없는
내용이라 사용자는 당황한다.

퀵메모는 "지금 이 노트를 쓰기 위한 작업대"인데, 데이터는 그렇게 모델링돼 있지 않았다.

## 결정

**퀵메모는 노트(탭)에 종속된다.** 노트 하나 = 퀵메모 하나. 노트가 죽으면 퀵메모도 죽는다.

이미 `inboxDraftStore` 가 노트 초안을 탭 id(`draftKey`)마다 관리하고, 탭이 닫히면 `clear(key)` 로
지운다. 퀵메모를 여기 얹으면 수명·영속·정리가 전부 따라온다 — 새로 만들 장치가 없다.

## 데이터

`InboxDraft` 에 두 칸을 더한다.

```ts
export interface InboxDraft {
  // ...
  memo: string;      // 퀵메모 원문
  memoOpen: boolean; // 이 노트에서 퀵메모 창이 떠 있나
}
```

- `quickMemo.ts` 의 `getMemoDraft` / `setMemoDraft` 는 **삭제**한다(전역 원문 저장소가 없어진다).
- **창 위치·크기(`quickmemo-pos`, `quickmemo-size`)는 전역으로 남긴다.** 그것은 메모의 *내용*이
  아니라 *창을 어디에 두고 싶은가* 라는 취향이다. 노트마다 창이 다른 자리에서 튀어나오면 더 나쁘다.

## 열림 상태

`PiecePoolApp` 의 전역 `memoOpen` useState 를 없애고, 활성 노트 탭의 `draft.memoOpen` 을 본다.

- 알약 버튼 · `⌘M` → `write(탭id, { memoOpen: !memoOpen })`
- **`⌘M` 은 노트(inbox) 탭에서만 동작한다.** 그래프·홈에는 퀵메모가 붙을 노트가 없다.
  (알약 버튼은 원래 Inbox 에만 있었다 — 단축키를 그 사실에 맞추는 것이다.)

## 정리본

`tidied`(정리 결과)는 **저장하지 않는다** — 최초 설계 그대로. 원문에서 언제든 다시 만들 수 있는
파생물이고, 저장하면 "원문과 정리본이 어긋난 상태"를 관리해야 한다.

결과: 탭을 옮기면 정리본은 사라지고 원문만 남는다. 정리한 글은 그 자리에서 복사해 노트에 붙인다 —
원래 그렇게 쓰는 기능이다.

## 마이그레이션 — 하지 않는다

기존 전역 메모(`quickmemo-draft`)가 **어느 노트 것인지 알 방법이 없다.** 아무 노트에나 밀어넣는
마이그레이션은 문제를 옮길 뿐이다. 키를 버리고, 사용자에게 사전에 알린다.

## 검증

- `inboxDraftStore.test.ts` — 탭 A 에 메모를 쓰고 탭 B 를 열면 B 의 메모는 비어 있다.
  `clear(A)` 하면 A 의 메모가 사라진다.
- 앱: 노트 A 에서 퀵메모 작성 → 노트 B 로 이동(창이 닫히고 빈 상태) → A 로 복귀(메모 그대로).
