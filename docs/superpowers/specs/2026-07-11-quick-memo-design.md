# Quick Memo — 설계

- 날짜: 2026-07-11
- 브랜치: `feat/quick-memo`
- 대상: `src/llm/tidy.ts`, `src/lib/quickMemo.ts`, `src/app/panes/QuickMemo.tsx`, `src/app/panes/InboxSection.tsx`, `src/app/PiecePoolApp.tsx`
- 관련 계약: 없음 (계약 변경 0, 새 엔티티 0, 새 파일 레이아웃 0)

## 배경 / 문제

강의는 실시간이고 이해는 그 속도를 못 따라간다. 학생은 의식의 흐름대로 갈겨쓴다 — 불릿, 반문장, 화살표, 자기만의 비유. 그 파편은 나중에 읽으면 자기도 못 알아본다.

기존 **정리 글 변환**(`synthesize.ts`)이 이 문제를 다루긴 한다. 그러나 방향이 다르다.

```
synthesize.ts SYSTEM_PROMPT:
  "하나의 논리적으로 정리된 마크다운 글로 재구성한다"
  "논리적 순서로 재배열하고 ## 헤딩으로 주제를 묶는다"
```

이것은 **AI 문체로 재작성**한다. "걍 어디를 볼지 정하는 거" 가 "입력 시퀀스의 각 위치에 가중치를 부여하는 메커니즘" 이 된다. 사실은 보존되지만 **학생의 흔적이 사라진다.**

이유가 있다. 사람은 자기 언어로 표현한 것만 진짜로 안다. 남의 문장으로 갈아치운 노트는 다시 읽어도 남의 것이다. 파인만식 되묻기(`feynman.ts`)가 "학습자가 설명을 생산한다"를 강제하는 것과 같은 원리다 — **표현의 소유권이 학습의 조건이다.**

Quick Memo 는 그 반대편을 맡는다. **구조는 정리하되 문체는 지킨다.**

## 목표 (성공 기준)

- 강의 중 **버튼 한 번**으로 메모장이 뜨고 바로 타이핑할 수 있다.
- `[정리]` 를 누르면 순서·제목·오탈자만 손보고 **내 문장·말투·비유·질문은 그대로 남는다.**
- 원문은 **어떤 경우에도 덮어쓰이지 않는다.**
- 메모는 자동 저장되어 앱을 껐다 켜도 남는다.
- AI 호출이 실패하면 **이유를 보여준다.** 조용히 폴백하지 않는다.
- 계약 변경 0. 새 의존성 0(클립보드 제외, 아래 리스크 참조).

## 범위 밖 (Non-goals)

- **별도 OS 창(always-on-top).** 줌·PPT 위에 띄우는 것이 이 기능의 이상형이지만, Tauri 창 생성 권한·설정·창 간 상태 공유가 필요하다. 1단계는 앱 안 플로팅 패널로 검증하고, 가치가 확인되면 별도 창으로 승격한다.
- **메모 여러 장 / 목록 UI.** "번잡하면 안 된다"가 최우선 제약이다. 노트·공간 관리는 이미 앱에 있다. 역할이 겹친다.
- **노트 에디터에 자동 삽입.** 복사 버튼으로 충분하다. 삽입 대상(커서 위치·현재 탭)을 추적하면 결합도만 올라간다.
- **오프라인 휴리스틱 정리.** 문체 보존은 LLM 없이는 의미가 없다. 키가 없으면 그 사실을 말한다.

## 설계

### 1. 진입점 — 알약 버튼

`InboxSection` 상단 알약 행(`AI 생성` · `되묻기`) 옆에 `✎ 퀵메모` 추가.

- 스타일: **강조 알약** — `border-primary` + `text-primary` + primary 틴트 배경.
- `AI 생성` 이 켜졌을 때와 같은 시각 언어다. 신규·핵심 기능이므로 조용한 회색 알약보다 도드라져야 한다.
- 다른 알약과 달리 **토글이 아니라 창을 여는 동작**이다. 눌린 상태를 유지하지 않는다.

### 2. 메모장 — 미니멀, 제자리 교체

화면에 보이는 요소는 **글 + 버튼**뿐이다. 탭도, 분할선도, 목록도 없다.

```
┌──────────────────────────┐
│  ═══                  ✕  │  ← 드래그 바 + 닫기
├──────────────────────────┤
│  어텐션 = 걍 어디를 볼지  │
│  정하는거                 │  ← textarea (모노스페이스)
│  Q K V ... -> 점수        │
│  softmax 때리면 확률됨    │
│                     ▌     │
├──────────────────────────┤
│  자동 저장됨      ✨ 정리 │
└──────────────────────────┘
```

`[✨ 정리]` 를 누르면 **같은 자리에서** 결과로 바뀐다.

```
┌──────────────────────────┐
│  ═══                  ✕  │
├──────────────────────────┤
│  # 어텐션                 │
│                          │
│  ## 핵심                  │  ← 스트리밍으로 흘러나옴
│  어텐션은 걍 어디를 볼지  │
│  정하는 거다.             │
│                          │
│  ## ❓ 왜 √dk로 나누지?   │  ← 내 질문이 질문으로 남음
├──────────────────────────┤
│  ↩ 원문         📋 복사  │
└──────────────────────────┘
```

- **원문 보존**: 원문(`draft`)과 정리본(`tidied`)을 각각 별도로 들고, 화면만 전환한다. `↩ 원문` 은 편집 모드로 돌아간다. 정리본이 원문을 덮어쓰는 경로는 존재하지 않는다. (`archive/` 원본 불가침 계약과 같은 정신)
- **드래그**: 드래그 바를 잡아 옮긴다. 위치도 저장된다.
- **자동 저장**: 타이핑이 400ms 멈추면 localStorage 에 기록.

### 3. 정리 LLM — `src/llm/tidy.ts`

`synthesize.ts` 의 구조(스트리밍·재시도·주입형 fetch)를 그대로 따르되 **프롬프트는 정반대**다.

```
너는 학생의 강의 메모를 정리하는 편집자다.
학생의 표현 방식을 지운다면 그것은 실패다.

[반드시 지킬 것]
1. 학생이 쓴 문장·어휘·말투·비유를 그대로 살린다.
   "걍", "때리면", "임", "->" 같은 표현을 교과서 문체로 바꾸지 마라.
2. 학생이 던진 질문("왜 ~?", "근데 ~?")은 질문 그대로 남긴다. 답을 채우지 마라.
3. 파편에 없는 내용을 추가하지 않는다. 일반 지식으로 보충하지 않는다.
4. 어떤 사실도 빼지 않는다.

[해도 되는 것]
- 순서를 논리적으로 재배열
- ## 헤딩으로 주제 묶기
- 오탈자·명백한 비문만 다듬기
- 목록/번호로 구조화, **볼드** 강조

[출력] 순수 마크다운. 첫 줄은 '# {주제}'. 코드펜스 금지.
```

규칙 2번이 특히 중요하다. 학생이 "근데 왜 √dk로 나누지?" 라고 적었다면 그것은 **모르는 지점의 표식**이다. LLM 이 답을 채워 넣으면 그 표식이 지워지고, 학생은 자기가 모른다는 사실조차 잃는다. 질문은 질문으로 남겨 되묻기(`feynman.ts`)의 재료가 된다.

- `streamChatText`(`stream.ts`) 재사용 — 결과가 실시간으로 흘러나온다.
- 모델은 `GEMINI_MODEL`(`gemini.ts`) 상수. 하드코딩 금지.
- 새 의존성 0.

### 4. 저장 — `src/lib/quickMemo.ts`

`settings.ts` 와 동형. localStorage 만 쓴다(이 기기에만 저장).

```
quickmemo-draft  : 원문 텍스트
quickmemo-pos    : 창 위치 {x, y}
```

정리본(`tidied`)은 저장하지 않는다. 파생물이고, 원문만 있으면 언제든 다시 만들 수 있다. 저장 대상을 늘리면 "원문과 정리본이 어긋나는" 상태를 관리해야 한다.

### 5. 실패 처리 — 조용한 폴백 금지

이 프로젝트는 방금 대가를 치렀다. `runWikiGeneration` 이 LLM 실패를 조용히 휴리스틱으로 덮으면서, `gemini-2.5-flash` 단종(404)을 팀 전체가 몇 주간 몰랐다. Quick Memo 는 그 실수를 처음부터 하지 않는다.

| 상황 | 화면 |
|---|---|
| 키 없음 | "AI 정리를 하려면 설정에서 Gemini 키를 넣어주세요" |
| 호출 실패 | "정리 실패: {사유}" + `[다시 시도]` |
| 스트림 도중 끊김 | 받은 만큼 화면에 남기고 오류 표시. 원문은 그대로. |

어떤 경우에도 **원문을 잃지 않고, 실패를 성공처럼 보이게 하지 않는다.**

### 6. 컴포넌트 경계

| 단위 | 하는 일 | 의존 |
|---|---|---|
| `tidy.ts` | 파편 → 정리본 (스트리밍). 순수 함수 + fetch 주입 | `stream.ts`, `gemini.ts` |
| `quickMemo.ts` | localStorage 왕복 | 없음 |
| `QuickMemo.tsx` | 창 UI·드래그·상태 전환 | 위 둘 |
| `PiecePoolApp.tsx` | 열림 상태 소유, 창 마운트 | `QuickMemo.tsx` |
| `InboxSection.tsx` | 알약 버튼 → `onOpenQuickMemo()` 호출 | 없음(콜백만) |

메모장은 앱 셸 레벨에 마운트한다. 탭을 바꿔도 살아 있다 — 스티커 메모의 성질이다.

## 검증 (통과 조건)

**단위 테스트**

- `tidy.test.ts`
  - 프롬프트에 표현 보존 지시가 포함된다 (규칙 1·2)
  - 스트리밍 델타가 누적되어 전체 텍스트가 된다
  - **실패 시 에러를 던진다** — 휴리스틱으로 조용히 대체하지 않는다
  - 모델명은 `GEMINI_MODEL` 상수를 쓴다 (하드코딩 회귀 방지)
- `quickMemo.test.ts` — localStorage 왕복(텍스트·위치)

**앱 end-to-end (수동)**

실제 파편을 넣고 정리해 **말투가 살아있는지 육안 확인**한다. 이것은 자동화할 수 없다 — 이 기능의 성패가 걸린 유일한 기준이다.

```
입력: 어텐션 = 걍 어디를 볼지 정하는거 / softmax 때리면 확률됨 / 근데 왜 루트dk로 나누지?
통과: "걍", "때리면" 이 살아있고, "왜 ~?" 가 질문으로 남아있다
실패: "메커니즘", "가중치를 부여하여" 같은 교과서 문체로 바뀌었다
```

그다음 복사 → 노트 에디터에 붙여넣기까지 확인한다.

## 리스크

**클립보드.** 앱에 복사 기능 전례가 0이고 Tauri 클립보드 플러그인도 없다. `navigator.clipboard.writeText` 가 Tauri 2 웹뷰에서 동작하는지 **구현 중 실제로 확인한다.** 실패하면 `tauri-plugin-clipboard-manager` 를 추가한다(의존성 1개 증가).

## 향후 (이 스펙 밖)

- **별도 OS 창(always-on-top)** — 줌·PPT 위에 띄워 진짜 "강의 중 필기"를 완성한다. 1단계 가치가 확인되면 승격.
- **질문 → 되묻기 연결** — 정리본에 남은 "왜 ~?" 를 파인만 되묻기의 시작점으로 넘긴다. 두 기능이 같은 원리(표현의 소유권) 위에 서 있으므로 자연스럽게 이어진다.
